## 2024-05-14 - Map arrays to Set in deep loops
**Learning:** The application heavily iterates over `state.routines` and `state.completions` during UI rendering loops. When evaluating active states inside these deep loops, always mapping arrays into O(1) `Set` objects beforehand prevents UI thread blocking from repeating O(N) array methods.
**Action:** Always create `Set` objects for lookups in tight loops, particularly for `id` filtering.
## 2024-05-15 - UI Loop Object Pre-allocation
**Learning:** In the `renderYearGrid` component, iterating through 365 days inside a UI component causes tremendous GC pressure and execution time because it inherently creates `new Date()` objects, loops repeatedly to check `.includes()` for array properties, and evaluates complex string interpolations millions of times over a lifecycle. Pre-computing invariant strings, avoiding deep template literals, and utilizing day-of-week modulo arithmetic with direct local date string comparisons reduces execution time of the matrix block by over 500%.
**Action:** When evaluating loops with hundreds of iterations (like rendering a year's worth of nodes), extract template logic strings upfront, pre-evaluate expensive booleans (`includes` arrays) into bitmasks or simple lookup tables, and avoid standard runtime object generation like `new Date()` by relying strictly on mathematical modulo patterns and standard character math.
