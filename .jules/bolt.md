## 2024-05-14 - Map arrays to Set in deep loops
**Learning:** The application heavily iterates over `state.routines` and `state.completions` during UI rendering loops. When evaluating active states inside these deep loops, always mapping arrays into O(1) `Set` objects beforehand prevents UI thread blocking from repeating O(N) array methods.
**Action:** Always create `Set` objects for lookups in tight loops, particularly for `id` filtering.
## 2024-05-14 - Pre-assemble HTML chunks in large calendar loop
**Learning:** In the large 365-day rendering loop of `renderYearGrid`, interpolating string templates inside the deep inner loop using dynamic properties (like `color`) incurs a measurable performance overhead. Pre-assembling these standard HTML chunks for each routine state (future, inactive, completed, missed) into a pre-allocated object before the loop avoids executing thousands of template literal interpolations and reduces memory allocation jitter/GC pressure, speeding up the render loop by ~8-10%. We also avoid O(N) array filtering like `Array.some(rt => rt.days.includes(dow))` inside the deep loop by precalculating routine bitmasks and using integer bitwise operations.
**Action:** When generating large HTML grids (like calendars), map out dynamic permutations into pre-assembled string caches outside the loop and append them, and use bitwise masks for schedule lookups.
