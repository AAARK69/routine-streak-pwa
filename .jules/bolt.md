## 2024-06-28 - Optimizer Bottleneck Identified and Solved
**Learning:** Found a critical performance bottleneck in `evaluateFitness` inside the genetic algorithm scheduler. The algorithm calls `evaluateFitness` heavily. The original overlap checks were O(n²) where n is the number of routines in a day, checking *every* pair of routines for overlaps. Additionally, the circadian energy limit check recalculated overlap for every hour (0-23) for every routine. Finally, cache string keys were built using `Array.prototype.join(',')` which is slow compared to character appending.
**Action:** The array of indices to evaluate was already sorted by `targetHour`. Because of this invariant, I could skip overlap calculations early (`if (start2 >= end1) break;`) for nested loops, reducing the overlap check to almost linear complexity since no routines further in the sorted array could possibly overlap. For circadian checks, I computed a flat `hourlyDemand` array in a single pass over the routines, then applied limits directly against it. These three micro-optimizations dramatically reduced the benchmark execution time of 10 runs of `optimizeAllSchedules` from ~2.2 seconds to ~1.1 seconds.
